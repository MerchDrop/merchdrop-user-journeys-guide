## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Auth error data → Sentry | Error objects from Supabase auth may contain email addresses in messages; review Sentry data scrubbing settings if PII is a concern |
| Checkout error data → Sentry | Payment errors should not contain card details (Paystack handles PCI); safe to capture |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Sentry event payload — auth errors | accept | Supabase auth errors contain only error codes and generic messages, not passwords or PII; safe to forward |
| T-03-02 | Information Disclosure | Sentry event payload — checkout errors | accept | Paystack errors contain transaction references, not card data (PCI scope is entirely Paystack's); safe to forward |
| T-03-03 | Elevation of Privilege | Missing Sentry capture on signOut errors | accept | signOut errors are already toasted by AuthContext; they indicate a Supabase API issue, not a security breach |
</threat_model>
